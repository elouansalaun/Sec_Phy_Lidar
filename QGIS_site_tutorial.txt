comment creer les champs dans field calculator

Le Field Calculator crée un champ et le remplit en une seule opération, à partir d'une expression.

Ouvrir le Field Calculator
Clic droit sur zones dans Layers, puis Open Attribute Table (ou F6).
Dans la barre d'outils de la table, clique sur l'icône de boulier Open field calculator (Cmd + I).
Créer le champ surface

Remplis la fenêtre ainsi :

Option	Valeur
Only update 0 selected features	décoché
Create a new field	coché
Create virtual field	coché (voir l'explication ci-dessous)
Output field name	surface
Output field type	Decimal number (real)
Output field length / Precision	12 / 1
Expression (grande zone à gauche)	area($geometry)

Sous la zone d'expression, Output preview affiche le résultat pour la première entité. Vérifie que la valeur est plausible en m². Clique ensuite sur OK : la colonne apparaît dans la table.

Créer poids_total et part_pct

Rouvre le Field Calculator pour chaque champ, avec les mêmes réglages :

Output field name	Expression
poids_total	"poids" * area($geometry)
part_pct	100 * "poids" * area($geometry) / sum("poids" * area($geometry))

part_pct donne directement la part de chaque zone dans la fonction objectif. C'est le chiffre qui compte.

Deux choix expliqués

Pourquoi area($geometry) plutôt que $area ?

$area calcule la surface sur l'ellipsoïde, selon les réglages du projet.
area($geometry) calcule la surface plane dans la projection de la couche, ici MTM 8.
Plus tard, geopandas et shapely calculeront des surfaces planes. Avec area($geometry), QGIS et Python donnent les mêmes chiffres. La différence est minime en MTM, mais c'est une bonne habitude de cohérence.

Pourquoi un champ virtuel ?

Il n'est pas enregistré dans le GeoPackage, seulement dans le projet .qgz.
Il se recalcule automatiquement si tu modifies une zone.
Une valeur dérivée ne doit pas être stockée dans les données sources. Ton script Python la recalculera lui-même.
